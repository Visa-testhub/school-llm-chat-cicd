Implementation

Browser -> Nginx -> Unix socket -> Gunicorn/Flask -> Ollama/MySQL. Conversation history is stored in MySQL and identified by a session ID stored in the browser's localStorage. I used the existing MySQL installation instead of MariaDB.

CI/CD

Ruff, pytest and Bash syntax checks are configured for pushes and pull requests. Tests use mocked Ollama responses and in-memory storage. Successful pushes to main are deployed using SSH, rsync and deploy.sh. The script installs dependencies, updates the schema and configurations, tests Nginx before reloading and restarts chatapp.service. Deployment is verified by comparing /viikko5/health with the commit SHA.

Users and security

The ubuntu user handles deployment. Gunicorn runs as the non-login chatapp user with www-data as its primary group. The MySQL user chatapp has SELECT and INSERT permissions. Application files are owned by ubuntu:ubuntu. Database credentials are stored in /etc/chatapp/chatapp.env. A separate deployment SSH key and known_hosts are stored in GitHub Secrets.

Ports 22 and 80 are open to all IPv4 addresses. SSH is open because GitHub runners use changing IP addresses. Password and keyboard-interactive authentication are disabled. Public SSH access increases exposure to attacks and the deployment key has access to a user with sudo privileges. MySQL replication access is restricted to Server B by a separate rule.

Nginx

Added include snippets/chatapp.conf to the existing school-site configuration. ProxyFix handles the /viikko5/ prefix. Previous locations were left unchanged.

Model and replication

I chose qwen2.5:0.5b because of its small size and CPU usage. No additional swap or server resizing was needed. The chatapp database is not replicated because the existing replication filter only includes viikko2_db.
